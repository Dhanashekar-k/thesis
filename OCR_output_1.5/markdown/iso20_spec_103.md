It is encouraged, but not required/mandated, to encrypt the contract certificate private key with unique ECDHE keys for every single SignedInstallationData packet sent by the SA to the SECC. Changing the ECDHE keys for every single SignedInstallationData packet sent by the SA to the SECC means if the EVCC sends three consecutive CertificateInstallationReq messages for the same contract certificate, it will get the exact same contract certificate with the exact same private key in all three SignedInstallationData in CertificateInstallationRes messages, but the encrypted data package (SignedInstallationData) will be unique in every single CertificateInstallationRes message. This requires that the SA encrypts the contract certificate private key and generate SignedInstallationData on-the-fly (i.e. when it gets the request from the SECC to provide the SignedInstallationData for a particular PCID). This improves security, but may add some delay in responding to CertificateInstallationReq especially in those cases where eMSP already stores the OEM provisioning certificate public key(s) and as such may have the data packets ready to go. It is left to the eMSP's discretion to design their system as they deem fit. This document does not mandate changing the ECDHE keys for every single SignedInstallationData packet sent by the SA.
