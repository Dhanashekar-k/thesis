Therefore, an automatic procedure for the installation of such a contract certificate is required: certificate provisioning. This procedure is supported by the charge protocol by offering the messages CertificateInstallationReq/Res. These messages transmit a contract certificate from a secondary actor (e.g. mobility provider) to the EV for installation and are secure by using encrypted communication. In order to enable certificate provisioning, activities which happen outside the charge protocol are required additionally. These activities are sketched in Figure H.13 and described in H.5.

### H.5 Offline contract certificate installation

As an alternative to the procedure described in 7.9.2.5 (and its subclauses), a contract certificate might be transmitted to the EV without using the charge protocol. This can be for instance necessary if the infrastructure, the secondary actor or the EV does not support the CertificateInstallationReq/Res, etc. In such cases the contract certificate that should be installed is transmitted to the customer (e.g. per postal mail, electronic mail) and then to the EVCC (e.g. using the diagnosis interface of the EV, a thumb drive and a dedicated USB socket in the EV, a telematics link to the EV). That means, all these transmissions occur offline and not via the charge protocol. The file (given to the customer) contains the certificate chain and the corresponding private key (similarly to CertificateInstallationRes). In order to avoid incompatible file formats and the necessity for the realization of transformation algorithms, a uniform file format can be used by all secondary actors when distributing contract certificate files, such as PKCS#12.
