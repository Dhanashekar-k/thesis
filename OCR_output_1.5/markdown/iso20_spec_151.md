[V2G20-2630] After a successful "Initial Handshake" (as described in 7.7.3.5) to setup a TLS session (as described in 7.7.3.3, 7.7.3.4 and 7.7.3.5), the SECC should calculate the SHA512 hash of the vehicle certificate (only the leaf certificate not the entire certificate chain).

NOTE 1 It is not in the scope of this document to define a methodology for the SECC to capture the vehicle certificate from the TLS handshake for the purposes of calculating the hash per this requirement.

[V2G20-2631] The SECC should securely store the hash generated by [V2G20-2630] until it is used per [V2G20-2550].

[V2G20-2550] Once a new SessionID has been assigned to the V2G session, the SECC should calculate the SHA512 hash of the SessionID of the V2G session concatenated with the hash generated by [V2G20-2630]. Refer to [V2G20-2106], [V2G20-2626] and [V2G20-2627] for details of SessionID assignment.

NOTE 2 SessionIDtoVehicleCertificateBinding = SHA512 (SessionID || SHA512 (vehicle certificate)).

[V2G20-2551] The SECC shall discard the hash generated by [V2G20-2630] after the hash has been utilized per [V2G20-2550].

[V2G20-2552] The SECC shall securely store the hash generated by [V2G20-2550] until the V2G session associated with the particular SessionID is terminated/closed.

[V2G20-2632] The SECC should securely store the hash generated by [V2G20-2553] until it is used per [V2G20-2633].

[V2G20-2553] Whenever the SECC performs the "Full Handshake" (as described in 7.7.3.5) to setup a TLS session (as described in 7.7.3.3, 7.7.3.4 and 7.7.3.5), it shall calculate a new hash by following [V2G20-2630].

[V2G20-2633] When the SECC receives a SessionID value in the SessionSetupReq that is equal to a SessionID value stored from a preceding V2G communication session that has not been terminated yet, the SECC should calculate the SHA512 hash of the SessionID received in SessionSetupReq message concatenated with the hash generated by [V2G20-2553].

NOTE 3 ReceivedSessionIDtoVehicleCertificateBinding = SHA512 (SessionID || SHA512 (Vehicle Certificate)).

[V2G20-2634] The SECC should discard the hash generated by [V2G20-2553] after the hash has been utilized per [V2G20-2633] or when the associated V2G communication session is terminated.

[V2G20-2554] The SECC should check that the hash value calculated by [V2G20-2633] is the same as the hash value calculated by [V2G20-2550].

[V2G20-2635] After a successful "Initial Handshake" (as described in 7.7.3.5) to setup a TLS session (as described in 7.7.3.3, 7.7.3.4 and 7.7.3.5), the EVCC should calculate SHA512 hash of the SECC certificate (only the leaf certificate not the entire certificate chain) or, in case of a private SECC, PE certificate (only the leaf certificate not the entire certificate chain).

NOTE 4 It is not in the scope of this document to define a methodology for the EVCC to capture the SECC/PE certificate from the TLS handshake for the purposes of calculating the hash per this requirement.

[V2G20-2636] The EVCC should securely store the hash generated by [V2G20-2635] until it is used per [V2G20-2555].
